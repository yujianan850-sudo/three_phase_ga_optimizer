**② ❗ 发现确定性代码缺陷**：`java_divide(..., 99)`

| 项 | 内容 |
| --- | --- |
| 位置 | `calculation/single_device_evaluator.py:145`，`_phase_quantities` 的 `Ddyyn11` 分支 |
| 现象 | `java_divide(p, TWO, 99)` → `scale()` 内 `quantize` 到 99 位小数，需 103 位有效数字，超出默认 `prec=28` ⇒ **必然** `InvalidOperation` |
| 实测 | **除 0 以外任何输入都失败**（0.5/1/2/100/6500/123456 全部 InvalidOperation） |
| Java 原文 | `LP = P.divide(BD_2);` —— **无 scale、无 rounding**，99 位是 Python 迁移**自行加上**的 |
| 影响面 | **全部 10 个 Ddyyn11 配置**（129/169/257/259/293/297/313/317/337/369） |
| 是否本轮引入 | **否** —— 冻结 zip（09-19）第 142 行同样存在 |
| 修好够吗 | **不够**。改用精确除法后，369 抽样 200 个候选仍 0/200，暴露出**第二层缺口**：高压层间纸档位表溢出（算到 10–15，表只有 0–9）、硅钢磁密损耗数据缺陷 |

⇒ **未修改任何源码**（改公式须先确认）。修复方案已通过 monkeypatch **验证有效**（能消除第一层故障），但**尚未落地**。

**③ 单设备六宫格覆盖**：圆形/长圆/椭圆 × 波纹/散热器 **六格全覆盖，缺失 0**（各有 Java 当次或快照记录 + 32 字段一致）。
