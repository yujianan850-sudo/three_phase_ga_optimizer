# 三相变压器优化原型：实验架构说明 V2

> 本文说明当前 Python 三相优化原型的整体架构：数据从哪里来、单设备精算器和 GA 如何协作、页面/命令行各自负责什么、结果写到哪里，以及当前验证边界。本文已同步至 2026-09-22 的代码与测试结论；测试证据见[测试总结报告.md](2026-09-21测试/测试总结报告.md)，其中部分既有 GA 轨迹仍为公式 v8，不可和公式 v9 或本轮算子调整后的运行混列。
>
> 核心 GA 流程已经实现。单设备精算器的当前公式版本为 v9；10 条真实 Java 记录的 320/320 个可比字段已精确一致。配置 401 已完成 20 个配对种子的四策略实验，但其结论仅限该配置、该搜索域、该预算和 v8 轨迹；不能将其扩展为工程最优性或全部产品的策略结论。

## 1. 架构结论

这不是三个互不相关的程序，而是一条固定的实验链路：

```text
Java 业务数据库（只读）
  ├─ 当前产品页面配置与允许范围
  ├─ 材料、铁芯、完整线规、冷却型号目录
  └─ 历史方案记录
             │
             ▼
Python 数据适配与搜索域构造
  ├─ 将 Java 记录还原为完整候选方案
  ├─ 将页面允许范围转换为本次合法搜索域
  └─ 选择同配置/相似配置历史结构种子
             │
             ├──────────────────────────┐
             ▼                          │
Python 单设备精算器                        │
  ├─ 对一个完整候选计算性能、重量、成本       │
  └─ 返回合格状态与约束诊断                 │
             ▲                          │
             │ 每个候选均重新精算             │
GA 搜索层 ───────────────────────────────┘
  ├─ 构造第 0 代
├─ 双档案、父代选择、结构电磁耦合交叉与探索性交叉、变异
  └─ 产生下一批待精算候选
             │
             ▼
本地 SQLite 轨迹（outputs/*.sqlite3）
             ▲
             │
实验页面 / 命令行入口
  ├─ 读取、启动、观察
  └─ 回放轨迹，不回写 Java 业务数据
```

最重要的职责划分是：

| 层次 | 唯一职责 | 不负责什么 |
|---|---|---|
| 单设备精算器 | 回答“这个完整方案算出来性能、成本和约束如何” | 不生成候选、不决定下一步搜索方向 |
| GA | 回答“下一步值得精算哪些合法候选” | 不复制变压器公式、不直接判定工程性能 |
| 页面/命令行 | 提供实验入口、展示和回放 | 不另建一套精算或 GA 逻辑 |
| SQLite 轨迹 | 保存本次搜索发生过什么 | 不作为 Java 业务方案数据 |

## 2. 数据和边界

### 2.1 数据从哪里读取

Python 通过 `config/database.local.yml` 以只读方式访问本机 `faladi` 数据库。主要读取：

- 三相产品页面配置：容量、电压、频率、损耗/阻抗/温升约束、油箱和工艺范围；
- 硅钢、铁芯、低压/高压完整导线记录、波纹片/散热器等目录；
- 当前配置和其它相似配置的历史方案记录。

Python 不读取 Java 服务的运行内存，也不依赖 Java 后端服务必须启动；但本地 MySQL 必须可读，才能发起新的精算和 GA 实验。

### 2.2 哪些信息是固定输入，哪些是 GA 候选

当前产品页面决定的是**固定需求和允许范围**。GA 只能在页面已允许的离散值中组合候选，不能自行扩大产品工艺边界。

| 类型 | 例子 |
|---|---|
| 固定输入 | 容量、电压、频率、损耗/阻抗/温升约束、价格条件、油箱类型、页面选定的线规筛选范围 |
| GA 候选 | 硅钢牌号、铁芯记录、低压匝数、完整低压/高压线规、层数、两侧油道、完整冷却型号、长圆 `conversionC` |

其中“完整线规”不是宽和厚两个可拆数字，而是“导线类别代码 + 目录记录 ID”的整体。高压类别代码可包括 QZ、QZL（价格字段兼容名 QQL）、ZBL、ZB、QZB、QZBL（兼容名 QQLB）等；具体允许哪些类别由页面多选范围决定。不同类别的同尺寸记录也属于不同目录对象，GA 只能整体选择、整体替换。

### 2.3 搜索域如何同步页面

`ga/gene_codec.py` 中的 `GeneDomain` 把当前页面和目录转换为合法候选域：

| 搜索项 | 当前来源与规则 |
|---|---|
| 硅钢/铁芯/完整导线/冷却型号 | 页面允许条件与真实目录记录共同过滤 |
| 低压匝数 | Java `optimizationScope.lowVoltageTurnsMin/Max`，页面缺失即拒绝构域 |
| 高压层数 | Java `craftHighCoil.minLayerCount/maxLayerCount`，页面缺失即拒绝构域 |
| 低压层数 | 不独立输入；箔绕等于低压匝数，线绕仅取 2 或 4 |
| 高、低压油道 | 页面各自的油道数量 × 油道类型组合；数量或类型为 0 时归一为无油道 |
| 长圆 `conversionC` | 仅长圆铁芯；该铁芯直径的 0.55～0.75，步长固定为 1 mm |

因此，搜索域是一次实验的“合法零件库”。页面没有允许、目录中不存在、或不满足派生规则的组合，不会进入 GA。

## 3. 单设备精算层：所有候选共用的裁判

位置：`calculation/single_device_evaluator.py`

精算器输入一条完整 `ThreePhaseDesignCandidate`，再结合当前配置和目录，计算：

```text
电气：P0、PK、UK 等
热工：油顶温升、低压/高压绕组温升等
结构：几何尺寸、油重、油箱重量等
经济：材料及总成本分项
诊断：是否可计算、公式是否完整、每项约束是否超限及超限程度
```

输出 `EvaluationResult`。GA 只使用它的三个层面信息：

```text
严格合格：可计算、公式完整、所有约束满足
近可行：可计算、公式完整，但仍有约束超限
不可计算：缺少数据或计算链无法完成，保留诊断但不伪造结果
```

同一候选在当前配置下只应精算一次；`EvaluationCache` 按完整候选编码缓存结果，重复候选命中缓存后不再重复调用公式。

Java/Python 的一致性验证同样使用这个精算器：历史 Java 方案先由 `record_adapter.py` 还原为候选，再在当前 Python 中重算并逐字段比较。它验证的是“同输入、同字段”的计算一致性，不等同于证明 GA 的寻优效果。

## 4. GA 搜索层

位置：`ga/`

GA 不会创造目录外零件。它提出一个个完整候选，精算器评价后，再基于结果决定哪些候选保留、组合或继续探索。

### 4.1 第 0 代：先覆盖，再引入经验和随机探索

`ga/optimizer_runtime.py` 负责构造初始种群。当前第 0 代不是“随机抽固定数量个方案”，而由四部分组成：

```text
多背景 A 层单项覆盖
+ 多背景 B 层关键两两覆盖
+ 同配置/相似配置历史结构种子
+ 随机完整合法候选
```

1. **分层背景**：从搜索域构造 1～6 条确定性完整背景，减少所有覆盖候选都围绕一个固定起点的偏向。
2. **A 层**：每个允许值至少出现在一个完整背景中，例如每条低压线规、每条高压线规、每个铁芯、每档匝数或油道均被覆盖一次。
3. **B 层**：对工程耦合较强的两两关系做均衡循环覆盖，例如铁芯 × 低压线规、低压线规 × 高压线规、铁芯 × 冷却型号。它不是所有两两组合的全枚举；小域研究如需穷举，需明确使用 `exhaustive` 策略。
4. **历史种子**：历史记录只提供结构起点，进入当前实验后必须重新精算；旧成本、温升和合格结论不能直接沿用。
5. **随机候选**：从完整合法域随机抽取此前未出现的候选，低压层数和 `conversionC` 同样遵守当前派生规则。

初始种群目标规模自动计算：先获得 A/B 覆盖去重数 `C`，再增加 `max(48, min(ceil(0.25C), ceil(4√C)))` 条历史/随机探索槽位。A/B 覆盖绝不截断，小搜索域仍允许覆盖完。第 0 代全量精算并更新双档案后，先将不可计算或结果不完整候选留在覆盖轨迹中、但排除在父代池之外；若可计算完整候选不足两条，则在不扩大页面允许域的前提下补抽未见完整组合，直到得到两个可作为交叉父代的候选或达到自动上限。仍不足两条时，运行带完整证据正常终止。否则从 `Ncalc` 条可计算完整候选中，按 `min(Ncalc, max(96, ceil(6√N0)))` 自动选取工作种群。该工作种群先保留双档案成员，再对硅钢、铁芯、完整高低压线规、低压匝数/层数、两侧油道、高压层数、长圆 `铁芯 × conversionC` 和完整冷却型号的代表进行轮询保留，最后按评价排序补足。轮询避免某个目录项数量很大时独占父代池。两个规模公式均为当前待标定策略，尚未用真实精算耗时、最低价保持率和漏解率证明最优。

### 4.2 相似配置历史种子

位置：`calculation/similar_history.py`

当新产品没有本配置的历史结果时，GA 会从其它兼容三相配置中寻找结构种子：

```text
先按产品配置相似度筛选来源配置
→ 还原来源方案使用的完整目录记录
→ 校验该结构是否仍在当前页面搜索域内
→ 按当前配置重新精算
```

当前相似度包含硬条件、主要设计条件和工艺条件。容量、电压、绕法/联结、铁芯、油箱、导线类别、硅钢等特征都单独记录得分。现有权重只是未标定的运行先验，不是用实验数据训练出来的权重。

相似历史目标数量按本次搜索域复杂度动态计算，限制在 5～30 条。若候选超过历史预算，按相似度优先级稳定保留；相同优先级保持既有排序，不使用随机数打散。每条迁入种子的来源配置、来源记录、旧价格、合规等级、相似度及特征分数会写入轨迹，为后续训练相似度权重保留数据。

### 4.3 评价、双档案与父代

位置：`ga/full_optimizer.py`

每一代精算后，优化器维护两个跨代档案：

| 档案 | 收录条件 | 排序目的 |
|---|---|---|
| 严格档案 | 可计算、公式完整、所有约束合格 | 以总成本优先，保留最终可推荐的方案 |
| 近可行档案 | 可计算、公式完整、存在约束超限 | 以总超限、最大超限、违规数、成本排序，保留接近合格边界的方向 |

当前种群则是“本代正在参与繁殖的全体个体”。它会每代替换，允许包含严格合格、近可行和较差候选；两个档案跨代保留。

父代选择规则：

```text
存在严格档案：
  父代 A 从严格档案的锦标赛选择中产生
  父代 B 以约 30% 概率从近可行档案选取；约 70% 概率从严格档案 + 当前种群选取

没有严格档案但有近可行档案：
  父代 A 从近可行档案选取
  父代 B 从近可行档案 + 当前种群选取

两个档案都为空：
  父代 A、B 都从当前种群选取
```

锦标赛选择不是永远拿排名第一，而是从小批候选中选更优者；它让高质量候选更容易繁殖，也给其它候选保留机会。

### 4.4 一代如何生成下一代

```text
上一代当前种群
  ├─ 精英保留：复制少量最优严格解；没有严格解时再使用近可行解
  ├─ 经验有效域随机注入：优先由已精算且可计算的候选随机重组未见完整组合；经验池不足时才回退原始域抽样
  └─ 填充剩余位置：选择父代 → 交叉或复制 → 可能变异 → 精算
                                                │
                                                └─ 更新严格/近可行档案
```

随机注入比例由 `optimizer.yml` 的 `random_injection_ratio` 给出，当前默认 0.10；它的比例基数是本代有效种群大小，不是扣除精英后的空位数。

### 4.5 结构电磁耦合交叉与独立冷却块

交叉不是把所有字段随意拆开。当前默认 75% 的交叉以“结构电磁块”整体继承，再单独替换完整冷却块；剩余 25% 保留四块探索性重组，以维持跨模块探索。

| 参数块 | 包含内容 |
|---|---|
| 结构电磁块 | 硅钢牌号、铁芯记录 ID、低压匝数、长圆 `conversionC`、低压完整绕组、高压完整绕组 |
| 冷却块 | 完整波纹片型号，或完整散热器型号 |

冷却块独立于铁芯块，因此可产生“父代 A 的铁芯 + 父代 B 的完整冷却型号”。但冷却块本身不可再拆：散热器中心距、片数、组数和 G/Q/SZ 目录记录必须来自同一个完整冷却型号。

探索性四块交叉时，低压层数会根据新子代的“低压导线类别 × 低压匝数”重新合法化，防止出现箔绕配 2 层或线绕配几十层的 Java 不可计算组合。

### 4.6 普通变异与定向变异

普通变异随机改变一个合法位置，例如整体替换一条完整高压线规、换油道、换铁芯、换冷却型号，或在合法范围中换 `conversionC`。它用于广泛探索。

定向变异只针对“已经精算、但尚未严格合格且存在可映射违规”的候选：

```text
归一化超限最大的一个主导项
→ 找到一个最直接的铁芯/低压/高压/冷却模块
→ 在对应模块的局部合法邻居中生成少量候选
→ 逐个重新精算并按结果选择
```

扁线和箔材局部邻居按“保持厚度、改变宽度”与“保持宽度、改变厚度”两个方向分别寻找完整目录记录，不再只按截面积判断方向。轨迹会保存主导约束、优先模块、基准候选和实际宽/厚/层数等调整动作。严格合格且无违规诊断的候选不会伪装为定向变异；若抽中定向变异概率，会回退为普通随机变异并在轨迹中标明来源。

定向变异中的“违规 → 模块”关联与局部探测数量已经实现。根据配置 445 的真实阻抗探测结果，阻抗方向保留“每侧最近同向油道”的规则，但删除铁芯兜底：4 条铁芯兜底均因硅钢损耗数据缺口不可计算，不能作为有效的阻抗局部修复。负载损耗违规则把完整线规邻居收紧为同方向的加宽/加厚/加粗或反向减小，避免将与违规方向相反的线规放入有限 probe。上述收紧仍须以当前 v9 的多种子实验验证其整体收益。

### 4.7 停止和末端细化

运行达到最大代数，或连续若干代没有改进时停止：尚无严格解时看最小近可行超限向量；已有严格解后只看最佳严格成本，近可行档案的小幅改善不会延长成本已经停滞的搜索。结束后，若存在严格合格方案，优化器会在成本靠前的少量严格精英附近做有限离散邻域细化，检查是否有同样严格合格但成本更低的邻居。

## 5. 轨迹、复盘与数据写入

位置：`ga/trace_store.py`、`ga/trace_reader.py`

每次初始种群预览或完整 GA 运行均写入一个本地 SQLite 文件：

```text
three_phase_ga_optimizer/outputs/
  initial-preview-{config_id}-{seed}.sqlite3
  ga-run-{config_id}-{seed}.sqlite3
```

`outputs` 仅保存本机实验轨迹；可按需要清理，业务数据库不会受到影响。

轨迹至少记录：

- 运行 ID、配置 ID、随机种子、搜索域摘要和 GA 设置；
- 每个候选的完整基因、精算结果、约束诊断和缓存命中情况；
- 候选来源、父代、交叉块来源、普通/定向变异来源；
- 候选是否进入严格档案或近可行档案、与同方案等价而未重复收录、被更优同方案副本替代、档案容量淘汰等真实原因；
- 首次进入严格可行域的代数；
- 历史种子的来源配置、历史记录、旧价格、合规等级和相似度明细；
- 每代种群摘要、档案快照、精算次数和缓存统计。
- 运行总耗时、单设备精算公式版本、核心代码 SHA-256 指纹、调用入口和实际生效策略。这些字段与配置 ID、搜索域指纹、种子、预算一起构成可比较实验的最小身份；文件名和文件修改时间不能替代它们。

候选轨迹在第 0 代或每个完整代结束时批量写入并提交。这样不改变精算、档案或随机数语义，但避免数千条候选逐条同步 SQLite；异常时只可能缺少未完成代，已完成代保持可回放。

在 Streamlit 页面中，若先完成第 0 代预览，随后以完全相同的配置内容、目录、页面范围、公式版本和候选集合运行 GA，GA 可复用预览精算结果。该复用仅限同一页面会话，且任何输入变化都会自动失效；命令行的独立运行不复用页面会话结果。

这些 SQLite 文件只用于实验复盘、论文统计和后续相似度/定向变异标定；不会回写 Java 业务数据库，也不会修改历史方案。

## 6. 两个实验入口

### 6.1 命令行入口

位置：`main.py`

适用于固定参数的批处理和重复实验：

```powershell
# 查看目录数量
& C:\ProgramData\anaconda3\envs\python310\python.exe main.py catalog

# 用一条历史记录核对已迁入的精算字段
& C:\ProgramData\anaconda3\envs\python310\python.exe main.py check-core --record-id 28859

# 只构造、精算并记录第 0 代
& C:\ProgramData\anaconda3\envs\python310\python.exe main.py initial-preview --config-id 445 --seed 20260903

# 运行完整 GA
& C:\ProgramData\anaconda3\envs\python310\python.exe main.py ga-run --config-id 445 --generations 20 --seed 20260907

# 按同一批种子运行四项策略消融；正式对照优先固定演化预算 B′
& C:\ProgramData\anaconda3\envs\python310\python.exe main.py ga-ablation --config-id 401 --seeds 20260918,20260919 --evolution-evaluation-budget 5000
```

命令行不再接收人工 `--size`。初始种群大小由当前搜索域、A/B 覆盖和自动规模规则决定。`--history-ratio` 与 `--random-injection-ratio` 可覆盖 `optimizer.yml` 的运行默认值。

### 6.2 实验页面

位置：`experiment_ui/app.py`

页面适合人工核对输入、手动精算、查看初始种群和回放轨迹：

```powershell
& C:\ProgramData\anaconda3\envs\python310\python.exe -m streamlit run experiment_ui\app.py
```

页面主要区域：

| 区域 | 用途 |
|---|---|
| 单设备精算 | 读取历史结构或手动选择完整候选，查看当前 Python 精算结果和约束诊断 |
| 一致性验证 | 选择 Java 历史记录，对比 Java 已保存字段与 Python 重算字段 |
| 初始种群诊断 | 构造并精算第 0 代，观察 A/B 覆盖、历史种子、随机候选和不可计算原因 |
| 完整 GA | 设置代数、交叉率、变异率、档案容量等运行策略，执行完整搜索并保存轨迹 |
| 轨迹回放 | 打开本地 SQLite，查看代际摘要、候选、父代和运行设置 |

页面读取数据库和目录时使用缓存；点击刷新会重新读取。数据库不可用时，可以回放既有本地轨迹，但不能进行新的精算或 GA 运行。

### 6.3 消融实验 CLI（当前已实现，页面对比入口尚未实现）

位置：`main.py ga-ablation`

页面适合人工查看候选域和单次运行；成组消融由 CLI 执行，保证整批参数可复核。页面、`ga-run --experiment-strategy` 和 CLI 批次共用四级策略映射：消融基线、仅耦合交叉、耦合交叉加经验有效域注入、完整诊断反馈策略。CLI 对同一产品配置、同一搜索域、同一批随机种子和同一种预算口径，依次运行这四项。每个“策略 × 种子”生成带唯一运行 ID 的独立 SQLite，并输出批次清单 JSON 和汇总 CSV；批次汇总同时记录每条运行耗时和运行证据。

预算不属于普通 GA 运行参数：页面和 `ga-run` 均可不填，此时按最大代数或停滞规则结束。总预算 `B` 是可选安全上限或小预算回归工具：真实调用单设备精算器达到 B 就停止；缓存命中不计入 B，但也不能在 B 达到后继续生成候选。另有演化预算 `B′`，只限制第 0 代完成之后的真实精算，初代覆盖成本单列为 `initial_evaluations`。只有 `ga-ablation` 的同配置、同搜索域、同种子策略对照至少须提供 B 或 B′ 之一；正式消融优先固定 B′，不将其用于不同产品间的强行比较。严格可行率只统计 `calculable=True`、`complete=True`、`feasible=True` 的候选，近可行候选不计入。

页面已有单次“本次实验策略”选择器，用于人工复核某一策略的实际 settings；它不替代 `ga-ablation` 的配对批次，也没有多轨迹统计显著性面板。任何策略优劣仍须从同配置、同域、同种子、同预算的 CLI 批次中计算。

## 7. 配置文件的角色

| 文件 | 作用 | 不应承担的职责 |
|---|---|---|
| `config/database.local.yml` | 本地只读数据库连接 | 不保存产品工艺范围 |
| `config/optimizer.yml` | GA 运行策略默认值：`history_seed_ratio`、`random_injection_ratio` | 不覆盖 Java 页面中的匝数、层数、油道或 `conversionC` 范围 |
| Java 三相页面配置 | 产品固定输入和允许工艺范围 | 不保存 Python 运行轨迹 |

## 8. 当前验证状态与后续实验

### 已经落地的架构能力

1. Java 数据只读接入、候选还原、搜索域构造、单设备精算和本地 SQLite 轨迹；
2. 页面范围驱动的匝数、层数、油道和 `conversionC` 合法域；
3. 多背景 A/B 初始覆盖、自动第 0 代规模、相似配置历史种子和随机完整候选；
4. 严格/近可行双档案、父代选择、结构电磁耦合交叉、少量探索性交叉、普通变异、定向变异、精英邻域细化；其中阻抗偏高/偏低优先对高低压径向油道做单侧、最近同向合法档位的离散探测，没有同向油道邻居则回退普通随机变异；负载损耗违规的完整线规邻居按加宽/加厚/加粗或反向减小收紧；
5. 历史种子相似度明细与交叉/变异/档案去向的轨迹留痕。
6. 消融所需的强制原始域注入、强制纯随机变异、总精算预算 B 和演化精算预算 B′；预算终止事实、初代/演化精算分列、唯一运行 ID 与入档前最后动作写入轨迹。

### 仍需真实数据验证的结论

1. 当前 v9 公式版本下，圆形、长圆、椭圆 × 波纹/散热器油箱的 Java/Python 全字段回归是否能保持 320/320 的对齐结论；
2. 自动初始规模、多背景 A/B、相似历史种子是否在相同精算预算下提高最低严格成本保持率并降低漏解率；尤其要记录第 0 代可计算完整比例与实际工作种群规模；
3. 结构电磁耦合交叉相对探索性交叉，是否提高严格解质量，以及是否带来可接受的精算次数与耗时；配置 401 的 v8 批次尚未检出额外效应，不等于所有配置均无效；
4. 定向变异是否比普通随机变异更快进入严格可行域；尤其阻抗违规下“最近油道优先、无邻居则随机回退”是否优于原先的深跳变油道探测或铁芯优先规则；
5. 相似度初始权重能否通过跨配置迁入样本训练为可解释、可验证的权重；
6. 标准 GA、随机搜索和不同算子开关在同一配置、同一随机种子集合下的比较。
7. v9 公式以及本轮父代筛选、不可计算子代筛除、阻抗油道回退和负载损耗线规方向调整后，重新运行消融基线、耦合交叉、经验有效域注入和诊断反馈变异；固定演化预算 B′、至少 10 个配对种子，额外报告耗时、磁盘占用和运行证据字段。

测试总结报告已完成配置 401、20 个配对种子、B′=8000 的 v8 四策略实验：经验有效域注入在该批次中有改善，耦合交叉和定向变异未检出额外统计收益；401 的油道域无法检验油道优先。由于本轮已调整公式和 GA 细节，旧批次保留为历史证据，不再作为当前代码的效果结论。401 仍可作为严格解对照主载体，415 可作中性参照；497 当前受可行历史种子锚定影响，445 在当前预算下无严格解，二者不宜直接承担严格成本主实验。完整执行顺序见[后续测试执行清单.md](2026-09-21测试/后续测试执行清单.md)。

因此，当前系统适合做“可追溯的计算与搜索原型实验”。它已经能够产生候选、保存过程和支撑对照研究；但在完整回归样本和多次真实实验之前，不应宣称已经稳定找到工程全局最优方案。
