## 2. 总体原则

1. **先取证、后写论文。** 任何正文数值必须能回溯到一份原始 Java 响应、一份 Python 输出或一份 SQLite 轨迹。
2. **Java 结果必须经 `faladi_mcp` 获取。** 不直接拼接或调用后端 HTTP 接口；测试记录中保存 MCP 请求名称、参数、返回时间和原始响应文件。
3. **同一场景内公平比较。** 所有方法共享配置快照、目录快照、价格快照、第 0 代构造规则、代码版本、随机种子和第 0 代后真实精算总预算 B′。
4. **B′是实验预算上限，不是日常 GA 默认限制。** 每个场景可以有不同的 B′，但同一场景的全部比较方法必须使用同一个 B′；第 0 代精算数单独记录，不计入 B′。
5. **不把失败硬填成成本。** 严格可行率与共同严格成功配对上的条件成本分别统计。
6. **不为凑图强行保留结论。** 例如某场景没有共同严格成功对，则不做该场景的成本 Wilcoxon/HL 推断；某个消融变体没有真实实现，则删除该变体，而不是用近似开关代替。
7. **当前主实验只选已可验证的 `Dy` 配置。** `Ddyyn11`、`Yy`、`Yd` 仍存在可计算率/历史记录映射等遗留问题（见本目录 `本批次测试进度.md`）。这些接线在缺口闭合前只作为后续扩展，不进入主统计结论。

## 4. 阶段 T0：真实场景筛选与输入冻结

### 4.1 目的

从真实三相配置中选出三个主场景，而不是沿用论文中虚构的 S1/S2/S3。选中的配置才在后续命名为 S1、S2、S3。

### 4.2 候选池与选择条件

优先从已有运行过且具备轨迹证据的配置中筛选：`401`、`415`、`505`、`508`；`445`可作为无严格解的负例，不作为需要成本对比的主场景。最终是否入选以本阶段实际导出的配置为准，不按编号或旧文档推断形状、容量或油箱类型。

三个主场景必须同时满足：

| 条件 | 判定 |
| --- | --- |
| 真实来源 | 能从数据库/Java 页面读取到完整配置，且通过 `faladi_mcp` 取得对应 Java 结果或历史记录 |
| 计算可用 | `initial-preview` 有完整可计算候选；5 个预试验种子中 BGA 与 MGA 均至少出现 3 次严格成功，或明确记录不作为成本比较场景 |
| 结构覆盖 | 三个场景合计至少覆盖两类铁芯形状、波纹与散热器两类油箱、低压/高压的实际目录线规选择；不强行要求某一个具体容量 |
| 油道覆盖 | 至少一个主场景任一侧油道候选数大于 1，以检验阻抗—油道局部探测；若实际候选不足，论文不得声称该规则已被效果验证 |
| 不混入未闭合分支 | 主统计阶段限定 `Dy`；若要纳入非 `Dy`，须先通过 T1 和 T2 的该接线一致性与可计算率门槛 |

### 4.3 执行步骤

1. 在实验页面和 CLI 分别读取候选配置，导出页面 JSON、油道候选、导线类别/记录数、铁芯与冷却记录数。
2. 对每个候选执行 `initial-preview`，保存 `GeneDomain`、第 0 代候选数、完整可计算数、不可计算原因分布和目录哈希。
3. 以 **BGA 与 MGA 各 5 个相同种子**进行不进入正式统计的预试验；禁止把这 5 个种子的结果混入后续 30 个正式种子。
4. 冻结场景：写入 `scenario_manifest.json`，包含真实配置 ID、页面快照、结构描述、目录快照、价格快照和种子池。

### 4.4 B′确定规则

对入选场景，读取预试验中 BGA 与 MGA 在自然停止时的“第 0 代后真实精算调用数”。取两种方法、5 个种子共 10 次运行的 **90% 分位数向上取整到 500**，作为该场景的正式 B′；若此值超过可接受计算资源上限，则换用更适合的配置，不以任意截断掩盖问题。

正式论文要明确：B′在预试验后、正式 30 种子运行前冻结；同一场景所有方法共享这一上限；预试验不参与显著性检验。

### 4.5 T0 通过条件与输出

- 产出 `scenario_manifest.json`、`domain_summary.csv`、`pilot_budget.csv`；
- 三个主场景的真实结构/容量/油道/冷却/目录规模均可还原；
- 每个场景的 B′有计算过程和原始调用数；
- 未通过的候选配置及原因保留，不删除；
- 通过后才允许将正式论文的 S1/S2/S3 绑定到真实配置。

## 5. 阶段 T1：Java—Python 单设备精算一致性数据采集

### 5.1 目的

把已有“320/320 一致”的结论重新固化为可复核数据包，同时补足三个主场景的直接证据。该阶段只验证同一候选的 Java 与 Python 是否一致，不评价 GA 策略优劣。

### 5.2 记录选择

1. 必跑已有 10 条真实记录：`28927–28933、28937–28939`，保持 32 字段口径；
2. 每个主场景至少增加 1 条真实 Java 历史记录或经 Java 页面保存的候选；
3. 优先覆盖：圆线/扁线、半/全油道、波纹/散热器、不同铁芯形状；
4. 无法唯一映射为 Python 完整记录的 Java 条目应记录为“不可复现”，不能静默跳过或用相邻线规替代。

### 5.3 固定测试流程

1. 通过 `faladi_mcp` 请求 Java 当前计算结果/快照，保存原始响应 JSON；
2. 用同一配置、同一完整目录记录和同一价格快照构造 Python 候选；
3. 调用 Python 单设备精算器，输出完整结果 JSON；
4. 按 32 字段逐一比较，金额字段以绝对误差、连续物理量以相对误差判定；
5. 生成 `java_python_field_diff.csv`：记录 ID、字段名、Java 值、Python 值、绝对差、相对差、阈值、通过/失败；
6. 生成 `consistency_summary.json`：样本数、字段数、通过数、最大相对误差、最大绝对金额误差、未覆盖分支。

### 5.4 通过条件

- 已有 10 条记录仍为 320/320；
- 新增记录全部逐字段通过，或论文明确缩小一致性覆盖范围；
- 任一字段失败即停止进入 T2，先修正公式或标注未覆盖；
- 论文中的“最大误差”“覆盖分支”只能从本阶段 `consistency_summary.json` 自动填写。

## 6. 阶段 T2：正式主比较数据采集

### 6.1 主比较范围

主比较只回答一个问题：在相同真实配置、相同初代和相同 B′上限下，**MGA 与目录约束基础遗传算法 BGA 的结果是否不同**。

| 项 | 固定规则 |
| --- | --- |
| 方法 | `BGA`、`MGA` |
| 场景 | T0 冻结的真实 S1、S2、S3 |
| 种子 | 每场景 30 个配对种子；两种方法对同一序号使用同一个种子 |
| 预算 | 使用 T0 冻结的、该场景第 0 代后真实精算总预算 B′ |
| 第 0 代 | 共享同一页面、目录、历史种子规则和随机种子；单独记录实际精算数 |
| 价格与公式 | 同一目录/价格快照、同一公式版本、同一 Git commit |
| 运行产物 | 每次运行独立 SQLite、单场景 manifest、汇总 CSV、完整日志 |

正式运行总数为 `3 场景 × 2 方法 × 30 种子 = 180` 条独立轨迹。任何中断、数据库连接失败或配置快照变化的运行均标记无效并以**同一 seed 重跑**，保留原失败日志但不得纳入统计。

### 6.2 每条轨迹必须提取的字段

| 论文指标 | 原始字段或计算方式 |
| --- | --- |
| 严格成功 | 最终严格档案是否非空；报告成功数/30 |
| 最低严格成本 | 严格档案第一名的总成本；失败运行为空值，不填惩罚成本 |
| 首次严格可行精算数 | 进入严格档案的首次真实精算调用序号；若第 0 代已得到，单独标识为 0 |
| 第 0 代后实际调用 | `evolution_evaluations`；与 B′、停止原因一起报告 |
| 近可行结果 | 最小归一化超限、最大超限、违规数、最终主导违规 |
| 搜索过程 | 每代最优严格成本、严格/近可行档案大小、缓存命中、候选来源 |
| 多样性 | 工作种群四模块平均汉明距离、严格档案不重复签名数 |
| 可追溯性 | `execution_entry`、`run_id`、代码指纹、公式版本、配置/目录/价格哈希 |

### 6.3 统计规则

1. 严格可行率：每个场景使用 MGA 与 BGA 的 30 对二元结果，报告成功数/30、不一致对 `(b,c)` 与双侧 McNemar 精确检验；
2. 成本：仅保留两方法均有严格解的相同 seed；报告样本量 `n`、中位数/IQR、双侧 Wilcoxon 符号秩检验、Hodges–Lehmann 估计、95% 置信区间和配对秩二列相关；
3. Holm：严格可行率的 S1/S2/S3 三项检验为一个 family；成本的三项检验为另一个 family；
4. 某场景没有共同严格成功对时，只报告可行率和近可行超限，不生成成本 `p` 值、HL 或成本森林图点；
5. 所有统计应由 `03_主比较_BGA_MGA/analysis.py` 从汇总 CSV 自动生成，禁止手工改数。

## 7. 阶段 T3：扩展对照、消融与失败模式

本阶段不是主比较的替代品；仅当对应变体真实可运行、设置能写入轨迹且不与主比较混淆时实施。

### 7.1 分层对照

若论文保留 RS、MGA-单档案和 MGA-Deb 的表 6 行，则每个真实主场景还需执行：

```text
3 场景 × 3 扩展方法（RS / MGA-单档案 / MGA-Deb）× 30 个同一种子 = 270 条轨迹
```

运行前必须做“变体真实性检查”：

- RS 确实是同一合法域内的结构化随机搜索，不调用遗传类末端细化；
- MGA-单档案确实没有独立近可行档案；
- MGA-Deb 确实使用 Deb 规则而不维护独立近可行档案；
- 三者均保留同一第 0 代、B′、价格快照和候选合法化函数；
- 若 CLI 或页面不能表达某个变体的真实设置，则不要用“近似策略”替代，论文中删除该行及相关结论。

### 7.2 消融

当前论文中的累积消融（无增强 GA → 双档案 → 覆盖初始化 → 经验注入 → 诊断反馈）也含构造数值。若保留表 8 和图 8，必须按冻结顺序跑真实数据：

```text
3 场景 × 5 个累积变体 × 30 个同一种子 = 450 条轨迹
```

表注必须保留：这是既定加入顺序下的累计描述，不能解释为单一模块的独立因果效应。若只打算证明某个模块的独立作用，应另设“完整 MGA 去掉一项”的配对消融，而不能从累积表倒推出因果结论。

### 7.3 多样性和失败模式

多样性与失败模式直接由 T2 的 BGA/MGA 轨迹导出，不另加运行：

- 图 9(a)：每代工作种群四模块平均汉明距离，绘制 30 个配对运行的中位数及四分位距；
- 图 9(b)：最终严格档案的完整记录签名数，明确上限为档案容量；
- 失败模式：分母为“最终未获得严格解的独立运行”，并在每个百分比后写实际条数，如 `33.3% (1/3)`；
- 当 MGA 失败样本过小，只作描述性说明，不报告机制因果结论。
