磁密表点缺失时由 `raise ValueError` 改为 `raise CandidateRejected`。

**Java 依据**：`ThreePhaseSchemeRecordServiceImpl.java:1240-1244`

```java
BigDecimal bj5 = CT.setScale(2, RoundingMode.DOWN);
if (brandConfigs.get(bj5) == null) { continue; }              // ← 缺数据 → 跳过候选
if (brandConfigs.get(bj5.add(BD_0_01)) == null) { continue; }
```

**语义**：数据缺失属「候选不可用」，不是「公式链缺失」，不得与首段精算失败混淆。

### G8 记录未固化配置快照 —— 🟡 已定位，已加判据

配置 497 的 `highVoltageSectionSpacing` 在 09-17 09:30–09:37 之间由 0 改为 60。
用 `ss=0` 复算 28917/28919 得 **361.50 / 447.20**，与 Java 保存值逐位吻合；
`ss=60` 得 428.50 / 514.20（Python 现值）。⇒ 老记录按旧配置算出，**不是 Python 缺陷**。

**判据**：T1 选记录必须满足「记录 `create_time` ≥ 配置 `update_time`」，
并用全库可复现性普查（`reproducibility_census.json`）复核。

### G9 老记录用旧版负载损耗公式 —— 🔴 新发现，需用户决策

`.add(HVECL).add(LVECL).add(SL).add(HVWLL).add(LVWLL)`。

全库 111 条有 `hvlvpk` 的记录：**54 条命中旧版（≤ 09-04 16:57）**、
**44 条命中现行（≥ 09-05 10:25）**，分界清晰无交叉。

**影响**：论文 T1 一致性只能声称覆盖「**记录 ID ≥ 28927 的 13 条 × 32 字段 = 416 字段值**」
（实测 100% 逐位一致）；其余 267 条因公式或字段格式版本不同**不可用于对照**。
**这 13 条全部不属于主比较场景**，故主比较的 Java 侧对照是**间接证据**。
