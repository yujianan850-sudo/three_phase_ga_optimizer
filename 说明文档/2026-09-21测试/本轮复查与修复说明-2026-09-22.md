## 2. 本轮实际修改

### 2.1 运行产物的可追溯证据

新增 `ga/runtime_provenance.py`。每次第 0 代预览、页面 GA、单次 CLI 和消融 CLI 运行，均写入：

- 单设备精算公式版本；
- 核心源码的 SHA-256 汇总指纹及逐文件指纹；
- 运行入口；
- 实际生效的实验策略；
- 本次运行耗时。

代码指纹覆盖精算器、搜索域、运行期缓存、GA 主循环、轨迹写入、CLI 和页面入口。其目的不是替代 Git 提交号，而是避免不同公式或不同算子版本的轨迹被误并入同一批统计。

`ga-ablation` 的 `summary.csv` 与 `manifest.json` 也记录每条运行的耗时和运行证据。

### 2.2 轨迹回放展示补齐

复查发现：上述字段虽已写进 SQLite 的 `settings_json`，但页面“轨迹回放 → 实验设置”仅展示旧参数，用户必须展开原始 JSON 才能看到版本和耗时。

已修改 `experiment_ui/app.py` 的 `trace_setting_rows()`，现在用中文展示：

- 结构电磁耦合交叉占比；
- 随机注入来源模式；
- 定向变异模式；
- 总预算 B、演化预算 B′；
- 本次实验策略、运行入口、耗时；
- 单设备精算公式版本；
- 核心代码指纹；
- 运行证据采集时间。

### 2.3 不可计算候选的处理

第 0 代仍按 A/B 覆盖、历史种子和随机候选全量评价，所有失败候选都保留诊断与轨迹证据。

后续代中，随机注入、交叉和变异产生的 `calculable=False` 或 `complete=False` 候选仍写入轨迹，但不占据工作种群槽位，也不会成为下一代父代。这样减少后续代反复围绕不可计算候选演化的浪费。

若原始第 0 代可计算且结果完整的候选不足两条，系统只在原页面允许域内补抽未见完整组合；成功找到两个起点后继续，达到自动上限仍失败时正常结束并留下终止证据。

### 2.4 定向变异收紧

根据配置 445 的真实阻抗探测记录：

- 阻抗偏高/偏低仍优先调整高压或低压其中一侧的最近同向油道；
- 不再使用铁芯邻居补足阻抗 probe 数量。历史测试中 4 条铁芯兜底全部因硅钢损耗数据缺口不可计算；没有同向油道邻居时，直接回退普通随机变异；
- 负载损耗偏高时，完整线规局部候选只保留加宽、加厚或加粗方向；偏低时只保留反向减小。圆线按直径判断，扁线/箔材按“同厚改宽”或“同宽改厚”判断；仍不会拼接不同记录的宽和厚。

以上是基于已有轨迹减少明确无效探测的实现调整，不等于已经证明整体寻优效果更好。

### 2.5 页面与 CLI 策略一致性

页面“本次实验策略”、`ga-run --experiment-strategy` 和 `ga-ablation` 共用同一个 `apply_experiment_strategy()`：

| 策略 | 耦合交叉 | 注入模式 | 变异模式 |
| --- | --- | --- | --- |
| `baseline` | 0 | 仅原始搜索域 | 仅普通随机变异 |
| `coupled` | 0.75 | 仅原始搜索域 | 仅普通随机变异 |
| `empirical_injection` | 0.75 | 经验有效域优先 | 仅普通随机变异 |
| `guided_mutation` | 0.75 | 经验有效域优先 | 单主导约束局部探测 |

页面预设用于单次行为核对；正式配对消融仍应通过 `ga-ablation` 固定配置、搜索域、种子与 B 或 B′ 执行。

## 4. 仍需测试和不能提前下的结论

### 4.1 第 0 代不可计算浪费

当前只明确减少了**后续代**不可计算候选占用工作种群的浪费。第 0 代继续保留全量覆盖，不应在没有可靠依据时删除目录值，否则可能漏掉在其他模块组合下可计算的候选。

若要降低第 0 代的不可计算比例，需要先从真实轨迹中将失败原因分为：硅钢磁密损耗数据缺口、绕组高度无法对齐、高压层间纸公式表越界等，并确认哪些失败只由局部静态条件决定。只有被验证为“同一条件下必然失败”的规则才可前置过滤。

### 4.2 当前 v9 多种子效果对照

配置 401 的既有四策略结果属于 v8 轨迹，不能直接作为当前代码的效果结论。应先执行专项回归，再用当前 v9 运行：

1. 5 个配对种子排练，估计耗时、磁盘占用和合适的 B′；
2. 固定配置、搜索域、公式版本、代码指纹、种子与 B′；
3. 至少 10 个、目标 20 个配对种子运行四种策略；
4. 分别报告严格解成功率、严格成本、最小近可行超限、首次严格解调用、耗时、磁盘占用及定向 probe 改善率。

详细操作与报告模板见[后续测试执行清单.md](后续测试执行清单.md)。
