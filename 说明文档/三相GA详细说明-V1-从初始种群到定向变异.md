## 0. 先建立共同语言：GA 中到底有哪些对象

如果没有这些概念，后面“种群”“档案”“父代”等词很容易混在一起。

| 名称 | 在本项目中的意思 | 例子 |
|---|---|---|
| 搜索域（Domain） | 本次产品允许 GA 选择的所有离散值集合 | 允许的 30 条低压线规、20 条高压线规、5 条铁芯等 |
| 候选方案（Candidate） | 一台完整待计算变压器的离散结构组合 | 铁芯 #3 + 低压线规 #18 + 高压线规 #7 + 匝数 52 + … |
| 精算结果（EvaluationResult） | 候选送入单设备精算器后得到的性能、成本、违规 | P0、PK、UK、温升、重量、成本、超限项 |
| 个体（Individual） | “候选方案 + 本次精算结果 + 来源 + 父代” | 第 4 代某候选，由 A/B 交叉后变异得到 |
| 种群（Population） | 某一代正在参与下一轮繁殖的个体列表 | 第 3 代的 200 个个体 |
| 严格档案（Strict archive） | 历史上已算出的严格合格方案中，成本最优的一小批 | 成本最低的前 24 个合格方案 |
| 近可行档案（Near archive） | 历史上已算出的不合格但离约束边界最近的一小批 | PK 只超 1%、温升合格的候选 |
| 一代（Generation） | 从上一代个体生成下一代个体的一次循环 | 第 0 代是初始种群；第 1 代开始发生交叉和变异 |

一个非常重要的区分：

```text
当前种群 = 这一代正在用来产生子代的一批个体
档案       = 从第 0 代到当前代，历史上最值得保留的一批结果
```

当前种群每一代都会整体替换；档案跨代保留，不会因为某个好方案暂时没进入下一代就忘掉它。

## 1. 整体执行流程

完整 GA 运行可看成下面这条链路：

```text
1. 读取本次产品固定输入和允许范围
2. 构建搜索域 Domain
3. 构造第 0 代初始种群
   ├─ A 层：全单项覆盖
   ├─ B 层：关键两两覆盖
   ├─ 历史种子
   └─ 随机补充
4. 对第 0 代每个候选做精算
5. 更新严格档案和近可行档案
6. 重复每一代：
   ├─ 精英保留
   ├─ 经验有效域随机注入
   ├─ 选择父代
   ├─ 块交叉
   ├─ 普通变异或定向变异
   ├─ 对新候选精算
   └─ 更新两个档案
7. 停止后，对少量严格精英做有限邻域细化
8. 输出严格档案、近可行档案和完整 SQLite 轨迹
```

这不是“GA 自己计算变压器”。GA 只负责不断提出完整离散候选；每个候选都要经过同一个单设备精算器，计算结果才决定它合不合格、成本高不高。

## 2. 搜索域：GA 本次到底允许改什么

`GeneDomain` 是“候选零件库”，不是最终方案。它先把每个可变位置允许的值列清楚，再由 GA 组合。

当前候选由以下结构组成：

```text
铁芯块：
  硅钢牌号
  铁芯记录 ID
  低压匝数
  conversionC（仅长圆）

低压块：
  低压导线类别
  低压完整线规记录 ID
  低压层数
  低压油道方案

高压块：
  高压导线类别
  高压完整线规记录 ID
  高压层数
  高压油道方案

冷却块：
  完整冷却型号
```

### 2.1 每个搜索项应从哪里来

| 铁芯记录 | Java 铁芯直径范围 + 页面选择的铁芯形状 + 铁芯目录 | 已按该逻辑构域 |
| 低/高压线规 | 页面选中的导线类别 + 真实目录；扁线再受页面宽、厚、宽厚比限制 | 已按完整目录记录构域 |
| 低压匝数 | Java `optimizationScope.lowVoltageTurnsMin/Max` | 必须读取；页面缺失时直接拒绝运行 |

### 2.2 低压匝数、高压层数和油道：现在怎样与 Java 页面同步

你的判断是对的。

Java 三相配置中已经有：

```text
低压匝数：optimizationScope.lowVoltageTurnsMin / lowVoltageTurnsMax
高压层数：craftHighCoil.minLayerCount / maxLayerCount
```

Python 不允许替代 Java 页面范围：

```text
Java 当前产品页面保存的范围
    ↓ 缺失
明确报错，不启动 GA
```
油道也不是 Python 的固定列表。以低压页面选择 `channelCount=[0,2]`、`channelType=[0,1,2]` 为例，Java 和 Python 都先作笛卡尔组合，再把任一侧为 0 的组合归一化：

```text
(0,0)、(0,1)、(0,2)、(2,0)、(2,1)、(2,2)
→ 去重、归一化后：无油道(0,0)、2 个半油道(2,1)、2 个全油道(2,2)
```

低压和高压分别各算自己的集合；不能因为低压页面允许 `(2,2)`，就让高压也自动拥有这个选项。
数据库里的旧配置可能把 `channelCount` 或 `channelType` 保存成单个整数，而不是数组。当前 Python 会像 Java 一样把标量 `2` 解释为 `[2]`，再参与上述组合；不会因为序列化格式不同而把整个产品错误排除在搜索域之外。09-24 全库核查后，143 个三相配置均可完成搜索域构造。

### 2.3 为什么导线必须保存类别和记录 ID

候选中的导线不是：

```text
线宽 = 0.5
线厚 = 0.2
```

而是：

```text
导线类别 = QZL（价格字段兼容名：QQL）
目录记录 ID = #101
目录族 = flat
```

或：

```text
导线类别 = QZBL（价格字段兼容名：QQLB）
目录记录 ID = #205
目录族 = flat
```

这里的“导线类别”是 Java/数据库的类别代码，不是业务人员手工填写的线宽标签。高压类别可包含 QZ、QZL（价格字段兼容名 QQL）、ZBL、ZB、QZB、QZBL（兼容名 QQLB）等；具体可选项由页面多选范围决定。这样做的原因不是“ID 本身比宽度重要”，而是一个 ID 才能稳定定位整条数据库记录以及对应类别分支。类别不同可能导致铜/铝属性、绝缘、价格、密度、排油系数、涡流系数不同。

因此不能写成：

```text
宽度来自 QQL 的 #101
厚度来自 QQLB 的 #205
```

这在数据库里可能没有对应材料，也没有明确的工艺含义。

### 2.4 “线宽要变大时，怎么找到对应 ID”

分两种情况。

#### 情况 A：普通随机变异

普通随机变异不说“线宽增大”，它从当前侧所有允许的完整导线选项中随机换一个。例如当前低压为：

```text
QQL + #101
```

允许域里还有：

```text
QQL  + #102
QQL  + #103
QQLB + #205
QQLB + #206
```

它可以整体切到其中任意一个。类别与记录 ID 同时替换。

#### 情况 B：定向变异中的“相邻线规”

定向局部探测需要“附近一点的线规”时，代码不是用 ID 大小判断，也不是自己把宽度加 0.1，而是：

```text
1. 取当前导线类别，例如 QQL；
2. 在 QQL 对应的真实目录记录中取全部允许线规；
3. 对扁线/箔材，找“厚度完全相同、宽度相邻”的真实记录，以及“宽度完全相同、厚度相邻”的真实记录；
4. 对圆线，才按直径找前一条、后一条完整记录；
5. 直接替换为该完整记录的 ID。
```

例如当前为 `QQL + #117 = 0.6 × 0.2`，目录还存在：

```text
QQL + #125 = 0.7 × 0.2  → 同厚，只增宽
QQL + #131 = 0.6 × 0.25 → 同宽，只增厚
```

局部探测会把 `#125`、`#131` 作为两个不同方向的完整记录候选；它不会按截面积把 `0.7×0.18` 也误称为“加宽一步”。若目录不存在另一维完全相等的记录，该方向就没有邻居，GA 不会拼出一个假规格。普通随机变异仍可在当前页面允许的各类别完整记录之间整体切换（例如 QZL/QQL 与 QZBL/QQLB），用于较大跨度探索。

## 3. 初始种群不是全组合：多背景覆盖怎样工作

假设暂时只考虑：

```text
低压线规：30 条
高压线规：20 条
铁芯：5 条
低压匝数：10 个值
低压层数：不是独立 4 个值；由“低压导线类别 × 当前低压匝数”派生
高压层数：5 个值
```

如果全组合枚举，候选数是：

```text
30 × 20 × 5 × 10 × 5 = 300,000（还未把低压层数的条件规则、油道、冷却型号算入）
```

这还没有乘硅钢、油道、冷却型号和 conversionC；真实全组合会更大。

初始种群**不是**一开始就计算这 600,000 个方案。它采用多背景单项替换的 A 层覆盖，以及关键两两组合的 B 层覆盖。

### 3.1 分层完整背景怎样构造

现在会先构造 `B1～Bk`（`k` 为 1～6）的确定性分层完整背景。每条背景都是当前搜索域内的合法组合：

```text
B1：铁芯 C1、低压 L1、高压 H1、匝数 40、合法低压层数、高压层数 8、油道方案 D1、冷却 K1
B2：铁芯 C2、低压 L2、高压 H2、匝数 44、合法低压层数、高压层数 10、油道方案 D2、冷却 K2
B3：铁芯 C3、低压 L3、高压 H3、匝数 48、合法低压层数、高压层数 12、油道方案 D3、冷却 K3
...
```

背景数量由各维度最大可选数决定，最多 6 条；它们按目录/范围的位置分层取值，目的是让覆盖候选不再都围绕排序首项。它们不是历史最优方案，也不代表系统认为它们最好。

### 3.2 A 层实际怎样替换

A 层仍然是“每次只覆盖一个指定取值”，但被替换的对象会**轮换不同背景**，而不是始终使用同一条背景。

例如有 30 条低压线规、3 条背景时：

```text
P1：在 B1 的基础上，把低压线规设为 L1
P2：在 B2 的基础上，把低压线规设为 L2
P3：在 B3 的基础上，把低压线规设为 L3
P4：在 B1 的基础上，把低压线规设为 L4
P5：在 B2 的基础上，把低压线规设为 L5
...
P30：在 B3 的基础上，把低压线规设为 L30
```

因此实际候选近似为：

```text
C1 + L1 + H1 + 匝数 40 + D1 + K1
C2 + L2 + H2 + 匝数 44 + D2 + K2
C3 + L3 + H3 + 匝数 48 + D3 + K3
C1 + L4 + H1 + 匝数 40 + D1 + K1
...
```

同样，高压线规、铁芯、低压匝数、高压层数、油道、冷却型号等 A 层覆盖也会轮换背景。低压层数始终跟随“当前低压完整线规类别 × 当前低压匝数”的 Java 合法规则派生，不能独立乱换。

所以 A 层当前的真实含义是：

> 每个允许值至少被精算一次，并且尽量分散到少量不同的完整合法背景；它不是全组合，也不表示该值已经在所有背景下验证。

### 3.3 A 层规模为什么仍远小于全组合

忽略去重时，当前初始化大致是加法关系：

```text
1～6 个分层完整背景
+ 低压线规覆盖约 30 个
+ 高压线规覆盖约 20 个
+ 铁芯、匝数、层数、油道、冷却等各维覆盖
+ B 层关键两两覆盖
+ 历史种子和随机补充
```

背景轮换改变的是“每条覆盖候选所在的上下文”，不会把 A 层扩大为“背景数 × 每个允许值”的全笛卡尔积。因此它仍远小于数十万、数百万个完整组合。

A 层只回答：

```text
“每个允许取值有没有至少被真正算过一次，并且不是都绑在同一条背景上？”
```

它不回答：

```text
“每个低压线规是否和每个高压线规、每个铁芯、每个冷却型号都算过？”
```

### 3.4 A 层之后是不是去 B 层交叉？

不是。A 层和 B 层都属于**第 0 代生成器**，不是遗传交叉。

```text
先构造 B1～Bk 分层完整背景
  ├─ 先把背景本身加入候选
  ├─ A 层：轮换背景，只替换一个指定维度值
  ├─ B 层：轮换背景，同时替换两个关键维度值
  │          例如铁芯 × 低压线规；不是把 A 层候选彼此交叉
  ├─ A/B 全部候选按完整基因去重
  ├─ 加入仍在本次域内、能唯一还原完整记录的同配置/相似配置历史方案
  └─ 按自动计算的第 0 代目标规模，再随机生成未出现过的完整合法候选
             ↓
        合在一起，才是第 0 代
```

实际候选数量由当前页面允许的铁芯、完整线规、匝数、层数、油道和冷却型号共同决定。当前代码会记录实际覆盖数、自动目标规模和最终第 0 代大小到轨迹。

### 3.5 多背景覆盖的当前边界

多背景能降低单一背景偏向，但不能证明已经充分检查所有耦合关系；B 层、历史种子、随机候选和后续 GA 仍然必要。背景数量上限 6、分层维度和是否引入历史背景都还没有真实精算数据标定；当前策略尚未证明为最优覆盖方案。

## 4. B 层：为什么还要关键两两覆盖

即使已有多背景 A 层，低压线规 L30 也只会出现在其中一条背景下，而不是和每个铁芯都配过。实际优势可能只在未被该背景覆盖的 C4 下出现。

因此 B 层专门补“两个因素同时变化”的关键关系。

### 4.1 例子：铁芯 × 低压线规

假设：

```text
铁芯：C1、C2、C3、C4、C5
低压线规：L1、L2、…、L30
```

完整枚举需要：

```text
5 × 30 = 150 个组合
```

默认均衡循环配对不算满 150 个，而是产生约 30 个：

```text
C1 × L1
C2 × L2
C3 × L3
C4 × L4
C5 × L5
C1 × L6
C2 × L7
...
C5 × L30
```

它的保证是：

```text
每个铁芯出现过；
每个低压线规出现过；
每个线规至少与某个铁芯组合精算过。
```

它不保证：

```text
L30 与 C1/C2/C3/C4/C5 都算过。
```

如果某个研究实验必须证明“铁芯与低压线规所有搭配都检查过”，必须显式采用 `exhaustive`，此时就是 150 个，不应该用默认 B 层冒充全覆盖。

### 4.2 B 层覆盖哪些关系

当前代码覆盖：

```text
硅钢 × 铁芯
铁芯 × 低压线规
铁芯 × 高压线规
低压线规 × 高压线规
低压线规 × 低压油道
高压线规 × 高压油道
铁芯 × 低压匝数
低压线规 × 低压匝数（同时派生正确低压层数）
低压线规 × 低压层数
高压线规 × 高压层数
铁芯 × conversionC（仅长圆且合法）
铁芯 × 冷却型号
```

这些不是说“其它关系永远不重要”，而是当前优先认为它们的工程耦合更强。后续应根据真实轨迹、公式分析和业务经验继续调整这张关系表。

其中 `低压线规 × 低压层数` 是“兼容覆盖”，不是普通二维笛卡尔积：固定一档低压匝数时，箔绕记录只配“层数=该匝数”，线绕扁线记录只配 2、4 层。Python 不会构造“箔绕 + 2 层”或“线绕 + 37 层”。

### 4.3 A/B 后的历史种子和随机补充

A/B 产生候选并去重后，再处理历史种子：

```text
历史方案能唯一还原完整铁芯和线规
且仍在本次允许域中
→ 才加入第 0 代。
```

当前代码中，最后会按自动计算的第 0 代目标规模补充未重复的完整候选；先放入相似/同配置历史种子，剩余槽位才由随机完整候选补足。页面和命令行入口（CLI）已移除“最低种群规模”的手工输入。

因此第 0 代不是：

```text
“随机抽 N 个历史方案”
```

而是：

```text
“覆盖优先、历史补充、随机探索补足”的混合群体。
```

### 4.3.1 最低种群规模自动计算

最低种群规模不由页面或命令行手工填写。用户只填写真实业务范围，GA 根据这些范围给出第 0 代目标规模。

自动计算不能简单写成“搜索域有 60 万个组合，就取 60 万个个体”。全组合依旧可能过大，且 A/B 覆盖本身已经保证每个允许值及关键配对至少被看见。当前实现先得到 A/B 去重后的覆盖候选数 `C`，再只增加一个随 `C` 缓慢增长的探索槽位：

```text
C = A 层和 B 层去重后的候选数
extra = max(48, min(ceil(0.25 × C), ceil(4 × sqrt(C))))
N0_target = C + extra
```

其中 `N0_target` 是第 0 代的自动目标规模，不再是人工填入的“最低种群”。该规则的目的不是少算 A/B 覆盖，而是防止覆盖数已经很大时，再生成数倍的随机候选；`extra` 既不低于 48 条，又不超过 `C` 的 25%，在大域中按平方根级增长。实际覆盖占比、最终第 0 代大小和随机/历史数量都会写入轨迹。常数 48、0.25 与 4 是当前待标定的运行默认值，不能视为已证明最优参数。

最终还要受两个边界约束：

```text
1. N0_target 不得小于 C：A/B 已生成的覆盖候选绝不能为了凑规模被截掉；
2. N0_target 不得超过本次能构造出的不重复合法候选总数：小域应允许直接覆盖完。
```

在 `C` 之外的剩余槽位，才由“相似/同配置历史种子”和“随机完整合法候选”共同填充。当前历史目标数为“剩余槽位 × `history_seed_ratio`”，历史候选不足时其余位置自动随机补齐；因此历史数据少时随机探索会自然增多。历史比例和自动规模常数仍需后续以真实数据一起标定。

这项设计只解决“第 0 代要多少个候选、剩余位置怎么分”。第 0 代完成后，还会从完整评价结果中自动选择较小的**工作种群**进入遗传迭代，见下一节。

### 4.3.2 第 0 代全覆盖与后续工作种群分离

第 0 代的职责是覆盖，不应直接等同于每一代都要繁殖的父代池。当前流程为：

```text
第 0 代全量候选
  → 每条都完成当前配置下的真实精算
  → 每条都参与严格档案/近可行档案更新并写入轨迹
  → 自动选出较小的工作种群
  → 第 1 代起只由工作种群交叉、变异和随机注入
```

若第 0 代共有 `N0` 条，其中可计算且结果完整的候选数为 `Ncalc`，后续工作种群大小为：

```text
Nwork = min(Ncalc, max(96, ceil(6 × sqrt(N0))))
```

选取前先剔除“不可计算”或“计算结果不完整”的第 0 代候选；它们仍完整保留在第 0 代轨迹、仍保留失败诊断并参与初代覆盖统计，但不再被误当作父代。精算器还会区分“候选违反 Java 的离散档位/几何筛选规则”与“公式真正异常”：前者使用候选拒绝语义记录并跳过，不会再被笼统写成铁芯精算失败。若原始第 0 代可计算完整候选不足两条，运行不会立刻把“覆盖没撞到可计算组合”误判成“产品无解”：它会在**同一页面允许域**内补抽此前未见的完整合法组合，直到找到两条不同的可计算完整候选，或达到自动恢复采样上限。

恢复采样不凭失败文本永久排除某个硅钢、铁芯或线规，因为“某一组合不可计算”不等于“该零件在所有组合下都不可计算”；它只跳过本次已经精算过的完整候选。上限随原始第 0 代规模自动计算，并受估计合法候选总数约束：`min(剩余估计合法候选数, max(2000, min(20000, 2 × N0)))`。恢复候选的来源为 `initial_recovery_sampling`，轨迹记录抽样尝试次数、上限和每条候选的原始失败/精算结果。

只有恢复采样后仍不足两条可计算完整候选时，运行才会正常终止（不是抛出裸异常），并在轨迹中写入“初代恢复采样未找到两个可计算完整候选”、原始覆盖数、恢复评价数、尝试数和上限。此时应检查硅钢磁密损耗表、绕组几何范围、高压层间纸档位和页面研究边界，而不能让不可计算候选继续盲目繁殖。

对于剩余的可计算完整候选，先保留严格档案和近可行档案成员；再分别为硅钢牌号、铁芯记录、完整低压/高压线规、低压匝数、低压层数、两侧油道、高压层数、长圆铁芯的“铁芯记录 × 直线段 C”以及完整冷却型号取当前排序最好的代表。代表不是按字段名称顺序一次性塞入，而是按模块轮流加入：每个模块每轮至多加入一条，避免低压线规数量很多时挤掉匝数、油道或冷却等方向。最后再按“严格合格优先、近可行超限向量优先、成本”的顺序补足。这里的“低压/高压完整线规”仍是**导线类别 + 完整目录记录 ID**，不会把宽度、厚度或类别拆开。

没有进入工作种群的第 0 代候选并未被删除，也不是“没有算过”：它们保留在 SQLite 轨迹中，并会被标记为“已完成初始覆盖，未选入后续遗传”。它们仍已影响双档案，且可在回放中查看。上述“模块代表轮询”是为了消除原先由模块数量/字段顺序造成的父代池偏向，已经实现，但其对最低成本保持率、严格可行率和漏解率的影响尚未经过多随机种子对照验证。平方根系数 6 和最小值 96 也仍是待实验标定的默认策略。

页面实验若先单独生成第 0 代，再以完全相同的输入运行完整 GA，系统可复用该预览的精算结果：复用条件为配置内容、目录、页面选择范围、公式版本及完整候选集合全部一致。GA 仍会单独记录自己的第 0 代候选和档案更新，只将这些候选记为缓存命中而不再次计算。页面会明确提示已复用的候选数；任一条件不一致时自动重新精算。

### 4.3.3 随机完整候选的实际抽样规则

随机补充不是任意拼数字，而是在当前合法域中分别随机选择硅钢、铁芯、完整低压/高压线规、低压匝数、高压层数、两侧油道和冷却完整型号。

```text
低压层数：从“当前低压完整线规类别 × 当前低压匝数”的合法层数中随机选
长圆 conversionC：从该铁芯直径 × 0.55～0.75、步长 1 mm 的合法值中随机选
```

因此随机候选不会把宽和厚拼接成目录外规格，也不会固定把线绕低压层数总取为 2 或把长圆 `conversionC` 总取区间第一个值。

### 4.4 相似配置历史种子

现在会读取当前配置之外的三相配置与历史记录，先按真实保存配置字段计算相似度，再以来源配置还原完整目录记录，最后严格校验硅钢、铁芯、完整线规、匝数、层数、油道和冷却型号是否仍属于当前页面域。旧成本、温升和合格结论不会直接沿用；每个入选结构必须由当前配置的 Python 精算器重新计算。

第一步不是直接比较某一条历史方案，而是先建立“配置相似度”。相似度应至少分为三层：

```text
硬条件：必须相同或兼容，否则不进入候选配置池
  例如三相类型、接线/绕组结构、可用铁芯形式、油箱大类等。

主要设计条件：决定电磁和结构尺度的输入，权重最高
  例如容量、电压组合、频率、损耗/阻抗/温升约束、铁芯直径范围等。

工艺条件：决定能否复用绕组与冷却结构的输入，权重次之
  例如高低压可选导线类别、扁线宽厚范围、油道选择、冷却型号范围等。
```

具体字段必须以三相 Java 页面实际保存的配置字段为准，不能只根据字段名称另外造一套“相似度参数”。每条相似度结果还应保存“哪些字段相同、哪些字段不同、各自扣了多少分”，以便人工核对。

第二步是动态决定保留多少条历史种子，而不是固定“前 5 条”或“前 10 条”。当前实现以本次搜索域复杂度作为基础：

```text
复杂度 = 铁芯数 × 低压完整线规数 × 高压完整线规数
         × 低压匝数值数 × 高压层数值数
         × 两侧油道组合数 × 冷却型号数
```

当前历史种子目标数按 `5 × ceil(log10(复杂度))` 计算，并限制在 5～30 条。代码会扫描其它兼容配置，按相似度排序后再选候选结构，而不是预先限制固定数量的来源配置。这个目标数区间尚未结合单次精算耗时、真实可用历史数量、最低价保持率和漏解率完成标定。

第三步是在相似配置的历史结果中选可用候选。当前规则按“配置相似度降序 → 历史记录的合规等级（`FULL` 表示该记录保存时标记为完整合规）优先 → Java 保存价格升序 → 记录 ID”排序，并对相同完整基因去重：

```text
1. 先排除无法还原完整目录记录、与当前页面范围不兼容的历史方案；
2. 对剩余方案优先选择历史严格合格、成本靠前的候选；
3. 历史合规等级不是 `FULL` 的记录仍可在后续位置进入候选池，但不高于完整合规记录；
4. 同一完整基因只保留一条。
```

“同一结构只保留少量、按结构差异主动挑选”的多样性策略尚未实现；目前只做完整基因去重，不能夸大为已完成结构多样性优化。

#### 4.4.1 相似度高的种子如何真正优先进入第 0 代

相似模块先形成候选池；如果历史候选数仍超过本次第 0 代留给历史的预算，初始化器不再随机抽样，而是按 `selection_priority` 降序稳定保留。

```text
跨配置历史种子：selection_priority = 配置相似度分数
同配置历史种子：默认优先级 = 1（因为产品配置完全相同）
相同优先级：保持候选池原排序，不再由随机数打散
```

所以在两个跨配置候选竞争有限历史位置时，相似度分高者必然优先。历史合规等级（`FULL`）和历史价格先用于形成相似候选池的排序；旧价格只用于预筛选，绝不替代当前配置重新精算后的成本。

#### 4.4.2 权重目前不能假装“已经算出”，但训练数据已经开始留痕

容量 0.16、电压 0.10 等值当前只是让相似度模块能够运行的**初始先验**，不是从真实效果训练出来的权重。只比较两份配置，不能知道“容量相似”究竟比“联结方式相似”更能预测候选迁入后的效果；必须观察历史结构迁入当前配置、重新精算后的真实结果。

每个跨配置历史种子会把以下内容连同当前精算 `result_json` 一起写入初始个体的 SQLite 轨迹 `operator_json`：

```text
source_config_id / source_record_id
source_compliance_level / source_price
similarity_score
similarity_feature_scores（容量、电压、绕法、联结、铁芯、油箱、导线类别、硅钢等逐项 0～1 分）
```

这些轨迹将形成训练样本：

```text
X：各特征相似度
y：重新精算后是否严格合格、总/最大超限、严格合格时的成本及相对排名
```

积累足够跨配置迁入样本后，应按产品类型分层，以训练集/验证集分开学习权重：先学习“是否进入严格可行域”，再学习“严格可行时成本是否有竞争力”，做交叉验证并记录模型版本和样本范围。之后才用训练结果替换初始先验；在真实迁入数据不足前，不能诚实地宣称权重已计算完成。

从其它配置迁入的候选，不能直接沿用它的旧成本、温升或合格结论。它只是一条**结构种子**；进入当前产品后必须按当前配置、当前目录和当前 Python 精算器重新计算。若某个历史结构不在当前页面允许域内，原则上应直接淘汰；若未来要支持“映射到当前最近合法完整记录”，必须单独记录为“投影种子”，不能伪装成原始历史方案。

最终第 0 代应形成：

```text
A 层：多背景单项覆盖
+ B 层：多背景关键两两覆盖
+ 相似配置的高质量历史种子
+ 随机完整合法候选
```

这样历史数据不再要求“新方案必须已有本配置的旧结果”，而是作为相似产品经验的起点；同时仍由当前精算结果决定新方案是否真正可行。

# 第二部分：双档案

## 5. 为什么既要当前种群，又要两个档案

可以把它想成三个不同用途的盒子：

| 盒子 | 存什么 | 用来做什么 |
|---|---|---|
| 当前种群 | 本代准备繁殖的全部个体 | 生成下一代 |
| 严格档案 | 历史最优的严格合格方案 | 保存最终候选、优先提供父代 |
| 近可行档案 | 历史上最接近合格边界的不合格方案 | 在没有/不足严格解时提供搜索方向 |

### 5.1 当前种群是什么

假设本代实际种群大小为 100。当前种群就是这 100 个本代个体：

```text
第 3 代 population = [I1, I2, I3, ..., I100]
```

它里面可能同时有：

```text
严格合格方案
近可行方案
严重不合格方案
甚至不可计算方案
```

为什么不只保留档案中的好方案？

因为当前种群承担“保持多样性、提供不同父代、探索新的组合”的任务。若只让档案里的少数最优方案繁殖，GA 很快会变成近亲复制，容易陷入局部区域。

### 5.2 严格档案

严格档案只收：

```text
可计算 + 公式完整 + 所有约束合格
```

例如：

| 候选 | P0 | PK | UK | 温升 | 成本 | 去向 |
|---|---|---|---|---|---:|---|
| A | 合格 | 合格 | 合格 | 合格 | 100000 | 严格档案 |
| B | 合格 | 合格 | 合格 | 合格 | 98000 | 严格档案，排 A 前 |
| C | 合格 | 合格 | 合格 | 合格 | 105000 | 严格档案，排 A 后 |

严格档案按成本排序。容量例如为 24 时，第 25 个成本更高的严格方案会被淘汰，但轨迹会记录它是“档案容量淘汰”，不是“不合格”。

### 5.3 近可行档案

近可行档案只收：

```text
可计算 + 公式完整 + 至少有一项约束超限
```

排序不是先看成本，而是先看“离合格有多远”：

```text
总超限更小
→ 最大单项超限更小
→ 超限项目更少
→ 成本更低
```

例如：

| 候选 | PK 超限 | 温升超限 | 总超限 | 成本 | 近可行排序倾向 |
|---|---:|---:|---:|---:|---|
| D | 2% | 0 | 小 | 94000 | 靠前 |
| E | 8% | 0 | 大 | 90000 | 靠后 |
| F | 1% | 3% | 中 | 92000 | 中间 |

D 即使成本高于 E，也更值得留下，因为它距离“可作为最终方案”更近。

### 5.4 为什么近可行档案要参与选择

假设只有一个严格解 A：

```text
A：合格，成本 100000
```

另一个候选 D：

```text
D：PK 仅超 2%，成本 94000
```

D 不能作为最终推荐，但它可能只要换一条高压线规、加一层、调整油道后就严格合格，且成本仍可能低于 A。

如果 D 因为“不合格”被立刻丢弃，GA 就失去了这个靠近低成本边界的方向。

所以近可行档案不是“错误方案集合”，而是“可能跨过约束边界的候选池”。

### 5.5 档案与当前种群如何共同选父代

代码当前逻辑：

#### 已经存在严格档案

```text
父代 A：从严格档案中选
父代 B：
  约 30% 概率，从近可行档案中选；
  另外约 70% 概率，从严格档案 + 当前种群中选。
```

这表示：严格方案是主干，但仍给近可行方案一部分机会参与组合。

#### 没有严格档案，但存在近可行档案

```text
父代 A：从近可行档案中选
父代 B：从近可行档案 + 当前种群中选
```

#### 两种档案都还没有

```text
父代 A、B：从当前种群中选
```

这里“当前种群”就是本代所有 100 个左右的个体，不是另一种档案。它让搜索保留新的、未进入档案的组合机会。

### 5.6 锦标赛选择是什么

父代不是永远取排名第一，也不是完全随机。代码使用小型锦标赛：

```text
从候选池随机抽最多 3 个
→ 在这 3 个中选更优的一个
```

好处是：

```text
排名更好的候选有更大机会被选中；
但不是 100% 垄断，仍会保留多样性。
```

# 第三部分：交叉和普通变异

## 6. 新种群是怎样扩展出来的

```text
每一代 = 精英保留 + 随机注入 + 交叉/复制 + 变异
```

设当前种群大小为 100、精英数为 2、随机注入比例为 10%。一代大概会这样生成：

```text
先放入 2 个精英副本
尝试放入 10 个尚未评价过的新随机候选
剩余 88 个位置通过“选择父代 → 交叉/复制 → 可能变异”填满
```

实际随机注入会受剩余位置限制；如果精英或其它步骤已占满位置，就不会超出种群大小，也不会先对最终无法进入本代种群的随机候选做无效精算或写入轨迹。高随机注入比例下，这个边界修正会使新旧版本即使使用相同随机种子，后续随机序列也不再逐条相同；这是去除无效候选后的语义修正，不是缺少轨迹记录。

## 6.1 精英保留

精英保留的意思是：把当前最值得保留的少数候选直接复制到下一代，避免一次交叉/变异后好方案全部消失。

优先级：

```text
有严格档案 → 从严格档案取最优精英
没有严格档案但有近可行档案 → 从近可行档案取精英
两个档案都没有 → 从当前种群取排序最优者
```

精英复制不是重新设计一个方案，完整基因与原候选相同；但它会作为新一代个体保留，并记录来源为 `elitism`。

## 6.2 每代经验有效域随机注入到底是什么意思

这部分不是“随机把已有个体再复制一次”，而是为了防止 GA 长期只在已有家族附近打转。

例如当前有效种群是 100，随机注入比例是 0.10：

```text
ceil(100 × 0.10) = 10
```

这里 `ceil` 意思是向上取整：

```text
9.1 取 10
10.0 取 10
10.01 取 11
```

第 0 代已经真实精算过大量候选。只要其中至少有两条“可完成计算”的候选，代码就不再直接从全量笛卡尔域盲抽，而是随机选一条可计算候选作为基座、另一条作为供体，并整体替换以下一个或两个块：

```text
结构电磁块：硅钢、铁芯、低压匝数、高低压完整绕组及油道、conversionC
冷却块：完整波纹型号，或完整散热器型号
```

之后仍逐个检查：

```text
这个完整基因编码以前有没有出现过？
出现过 → 丢弃，继续抽；
没出现过 → 加入下一代。
```

“以前”不仅指当前一代，也包括这次 GA 运行里已经评价过的候选。经验池不足两条时，才明确退回“原始页面搜索域随机抽样”，轨迹会写出该回退原因。这个机制只是减少已知不可计算组合的盲目抽样，不会把页面允许范围改小，也不能当作性能公式的预判。

为什么比例基数用 100，而不是“精英保留后的 98”？

因为产品设置的语义应该是：

```text
本代希望约 10% 的探索力量用于真正的新方案。
```

而不应该因为本代保留两个精英，就偷偷把探索目标变成：

```text
98 × 10% ≈ 9.8 个。
```

最后如果只剩 5 个位置，即使目标是 10 个，也最多只能放 5 个；这是物理位置上限，不是改变比例含义。

## 6.3 块交叉

交叉的意思是：选两个父代，把它们的某些完整模块组合成子代。

假设两个父代：

| 模块 | 父代 A | 父代 B |
|---|---|---|
| 铁芯块 | 硅钢 M1、铁芯 C1、匝数 48、conversionC 300 | 硅钢 M2、铁芯 C4、匝数 54、conversionC 330 |
| 低压块 | QQL + #101、4 层、1 个半油道 | QQLB + #205、2 层、2 个全油道 |
| 高压块 | QQL + #301、12 层、无油道 | QQLB + #402、16 层、1 个全油道 |
| 冷却块 | 完整冷却型号 K1 | 完整冷却型号 K3 |

当前默认 75% 的交叉采用**结构电磁耦合继承**：铁芯块、低压块和高压块共同来自同一个父代；冷却块可独立来自另一父代。例如：

```text
结构电磁块取 A
冷却块取 B
```

那么子代就是：

```text
硅钢 M1、铁芯 C1、匝数 48、conversionC 300
低压：QQL + #101、4 层、1 个半油道
高压：QQL + #301、12 层、无油道
冷却：完整冷却型号 K3
```

这里有三个底线：

1. 结构电磁块内部的硅钢、铁芯、匝数、高低压完整线规、层数和油道不被拆开；
2. 波纹/散热器型号整体来自冷却块父代，不拆 G/Q/SZ；
3. 仍有默认 25% 的探索性交叉允许原有四块独立重组，但同样会执行低压“导线类别 × 匝数”的合法化。

所以块交叉解决的是：

> 把已经在不同父代中验证过“还算合理”的模块组合起来，而不是无约束打乱每个字段。

这里有一个必要的合法化步骤：低压匝数属于铁芯块，而低压线规来自低压块。若两个块来自不同父代，低压层数不能机械照抄低压父代。例如子代采用箔绕导线、铁芯块给出低压匝数 48，最终层数必为 48；若采用线绕扁线，最终层数只能是 2 或 4。该步骤防止块交叉产出 Java 不可计算的低压层数组合。

这样做是因为三份实际轨迹中，块交叉是严格解的主要来源，但四块完全独立重组会产生大量重复或工程耦合被打散的候选。75% 只是基于该诊断的初始值，尚需同配置、多随机种子消融实验标定。

### 6.3.1 冷却型号作为独立交叉块

```text
结构电磁块：硅钢牌号、铁芯记录 ID、低压匝数、conversionC、完整高低压绕组
冷却块：完整冷却型号
```

交叉时，冷却块可以独立从父代 A 或 B 选择。因此，父代 A 的结构电磁块和父代 B 的冷却型号 `K2` 可以组合，再由精算器判定这组铁芯/油箱/冷却组合是否可行。探索性交叉才会把电磁结构进一步拆成铁芯、低压、高压三个块。

冷却块始终是不可拆的完整型号：波纹油箱只替换完整波纹片记录；散热器仍以完整的中心距、片数、组数及 G/Q/SZ 三条目录记录作为一个整体，绝不跨父代拼接这些子字段。B 层仍保留“铁芯 × 冷却型号”的重点覆盖，用于在第 0 代直接检查这类耦合关系。

该规则已写入交叉逻辑；尚未用真实 Java/Python 对照样本验证它对严格合格率、最低严格成本、精算次数和耗时的实际影响。

## 6.4 交叉之后不一定变异

交叉率默认 0.85：

```text
85% 概率：执行块交叉；
15% 概率：直接复制父代 A。
```

然后才看总变异率，默认 0.45：

```text
45% 概率：对子代继续变异；
55% 概率：保持交叉/复制结果，直接精算。
```

因此不是“每个子代都交叉且都变异”。

## 6.5 普通随机变异

普通变异一次只改一个可变项目，从以下动作中随机选一个：

```text
换硅钢牌号
换铁芯记录
换低压匝数
换低压层数
换高压层数
换低压油道
换高压油道
换当前长圆铁芯合法范围内的 conversionC
整体替换低压导线类别 + 线规 ID
整体替换高压导线类别 + 线规 ID
整体替换完整冷却型号
```

例子：当前低压是：

```text
QQL + #101 + 4 层 + 1 个半油道
```

一次普通变异可能只发生其中一个动作：

```text
换低压导线：QQLB + #205 + 4 层 + 1 个半油道
```

或：

```text
换低压层数：线绕导线可在 2 层和 4 层之间切换；箔绕导线没有独立“换层数”动作，因为层数永远等于低压匝数
```

不会一次默认把线规、层数、油道全部改掉。这样可以保留“这一次变化到底产生了什么影响”的可解释性。

换铁芯时还会做合法化：

```text
换为圆形/椭圆铁芯 → conversionC 清空；
换为另一条长圆铁芯 → conversionC 调整到新铁芯自己的 0.55–0.75 合法离散域。
```

# 第四部分：定向变异

## 7. 定向变异和普通变异的关系

```text
普通变异：
  “我随机换一个合法零件/档位，看看会不会更好。”

定向变异：
  “这个方案主要是 PK 超限，我优先在可能影响 PK 的模块附近试几种合法变化，
   但到底改善不改善，仍由重新精算决定。”
```

```text
交叉：组合两个父代已有的完整模块；
普通变异：随机改一个合法参数；
定向变异：针对当前不严格合格候选的违规，优先试相关模块的局部合法变化。
```

但有一个补充：当前实现只在评价结果存在可映射的违规项时才做定向局部探测。严格合格、且没有违规项的子代即使抽中了“定向变异”概率，也会明确退回普通随机变异，轨迹记为 `random_mutation_no_diagnostic_direction`；它不会把全模块试探伪称为定向变异。若以后需要对严格解做成本导向局部搜索，应作为独立算子实现和统计。

## 7.1 定向变异什么时候触发

子代已决定要变异时，再按 `guided_mutation_rate` 决定走哪条路。

默认值：

```text
总变异率 = 0.45
定向变异比例 = 0.65
```

含义是：

```text
100 个子代中，约 45 个会变异；
这 45 个中，约 65%（约 29 个）尝试定向变异；
其余约 16 个走普通随机变异。
```

这不是严格固定数量，因为每次由随机数决定。

## 7.2 先从违规中找“优先模块”

精算器返回每条违规，包括实际值、限值、超限方向和归一化超限程度。

当前先按归一化超限值选出**一个主导违规**，再按下表构造局部探测候选。下表是当前实现的优先规则，不是已经由统计实验确认的因果结论；每个候选仍须重新精算后才可能被保留。

| 主导违规 | 当前优先探测 | 次级探测或回退 |
|---|---|---|
| 磁密 `flux_density`、空载损耗 `no_load_loss` | 铁芯模块 | 普通随机变异 |
| 负载损耗 `load_loss` 偏高 | 铜损较高的一侧绕组模块；只试相邻的加宽、加厚或加粗完整线规 | 普通随机变异 |
| 负载损耗 `load_loss` 偏低 | 铜损较高的一侧绕组模块；只试相邻的减宽、减厚或减细完整线规 | 普通随机变异 |
| 阻抗 `impedance` 偏高/偏低 | 高、低压径向油道；每条候选只改其中一侧，且每侧只试最近同向合法档位 | 没有同向油道邻居时直接回退普通随机变异 |
| 顶层油温、波纹膨胀、散热器中心距 | 冷却模块 | 普通随机变异 |
| 名称以 `lv_` 开头的违规 | 低压模块 | 普通随机变异 |
| 名称以 `hv_` 开头的违规 | 高压模块 | 普通随机变异 |

阻抗不是简单地“换一条铁芯”就能解释的指标。当前规则读取违规方向：阻抗偏高时，优先从 Java 页面允许集合中寻找同侧更少/更小的半油道或全油道方案；阻抗偏低时，寻找更多/更大的方案。高低压两侧各只先放入**距离当前油道最近的一个同向合法选项**，再交错进入局部探测队列，避免在探测槽位很少时直接把“2 个全油道”跳到“无油道”这类跨多个离散档位的深跳变。若没有同向油道邻居，不再用铁芯邻居补足探测数量，而是回退普通随机变异：真实轨迹中的铁芯兜底探测全部落入硅钢磁密损耗表缺口、成为不可计算候选，继续保留该兜底只会消耗精算。这里的“更少/更大”和“最近”只用于缩小离散探测方向；半油道、全油道的实际径向几何、漏抗和其他指标仍由精算器逐条计算判定，不能把数量/类型顺序当作已验证的单调结论。

例如某方案主要问题是：

```text
PK 超限 5%
高压电流密度超限 1%
```

代码会得到：

```text
铜损更高的一侧绕组模块
```

它不会先花大部分局部探测次数去换波纹片。

## 7.3 “局部”具体是什么意思

定向变异不是在整个搜索域里盲抽，而是先找当前位置的相邻合法档位。

### 铁芯模块局部邻居

可能包括：

```text
相邻硅钢牌号；
同铁芯形状下相邻铁芯记录；
相邻低压匝数；
当前长圆铁芯相邻 conversionC。
```

### 低压模块局部邻居

可能包括：

```text
当前导线类别内的“同厚相邻宽度”完整记录，或“同宽相邻厚度”完整记录；圆线则为相邻直径记录；
线绕低压导线在 2/4 层之间的相邻合法档；箔绕没有独立层数邻居；
本侧页面允许油道集合中的相邻选项。
```

### 高压模块局部邻居

同理，只作用于高压完整线规、层数、油道。

对于负载损耗违规，还会额外固定线规的局部方向：偏高只保留“更粗圆线”或“同厚更宽 / 同宽更厚”的扁线、箔材记录；偏低只保留相反方向。它仍是完整目录记录替换，不会拼接宽度和厚度。层数与油道的局部邻居仍可参与同一绕组模块探测，因为它们也可能影响损耗；但线规候选不会再混入反方向，减少已知与当前损耗方向相反的试探。

### 冷却模块局部邻居

只替换相邻完整冷却型号：

```text
波纹片：相邻真实记录；
散热器：相邻完整中心距/片数/组数 + G/Q/SZ 组合。
```

不会只换散热器 G 重量行、不换 Q 油重行，这种组合没有业务意义。

## 7.4 为什么还要限制局部探测次数

旧版本会把多个违规映射到多个模块，再从全部邻居中随机抽取。这会让 3 次 probe 分散到彼此无关的方向。当前一个定向变异只围绕一个主导违规构造候选；阻抗是例外：它的“径向油道”是一个虚拟优先模块，候选会在高压油道和低压油道之间交错，但每条候选仍只改一侧油道。油道候选不足时不再补入铁芯邻居，避免将已知数据表缺口导致的不可计算候选写成阻抗定向探测。

例如：

```text
低压导线同厚邻近宽度 2 个
低压导线同宽邻近厚度 2 个
低压油道邻居 1 个
共 5 个候选
```

如果每次定向变异都把 5 个或更多局部候选全部精算，计算量会迅速膨胀。

因此当前代码会：

```text
收集该模块的局部候选
→ 去重
→ 打散
→ 最多取 local_probe_limit 个精算
```

默认 `local_probe_limit = 3`。

也就是说，上述 5 个候选可能只随机挑 3 个真正精算。轨迹会写入主导约束、优先模块、基准候选 ID 和实际动作，例如“低压导线宽度增加”或“高压层数相邻调整”；是否改善仍必须通过精算结果判断。

## 7.5 定向变异如何决定是否采用结果

定向探测后，会把：

```text
原始候选
+ 最多 3 个局部探测候选
```

一起排序。

排序规则：

```text
严格合格优先；
严格合格之间，成本低优先；
都不严格合格时，总超限小优先；
再比最大超限、违规数、成本。
```

只有发现局部候选比原始候选严格更优时，才采用它。

如果三个局部候选都没有改善：

```text
回退到一次普通随机变异。
```

因此“定向”不等于代码认定某个方向一定正确；真正决定方向的是重新精算后的比较。

## 7.6 当前定向变异的证据边界

当前已经能确认：

```text
它只产生合法离散候选；
每个探测候选都会真实精算；
没有改善会回退；
轨迹会记录探测来源、父代、违规和档案去向。
```

当前不能确认：

```text
PK 超限时优先动绕组一定最快；
磁密/P0 时优先动铁芯一定最好；
local_probe_limit=3 对所有产品都合适；
定向变异一定比纯随机变异更快找到低成本严格解。
```

这些需要后续通过多个产品、多个随机种子做对照实验统计：

```text
违规类型
× 优先模块
× 实际变异动作
→ 尝试次数、改善次数、平均超限下降、首次严格合格率、成本变化、耗时。
```

## 8. 最后一步：为什么还要做严格精英邻域细化

GA 正式代数结束后，代码只对严格档案最靠前的少量候选再做一次有限局部搜索。

流程是：

```text
取前 local_refine_elites 个严格合格候选
→ 对铁芯、低压、高压、冷却模块生成相邻合法方案
→ 最多精算 local_refine_limit 个
→ 只更新档案，不再把它们当作下一代种群
```

它的目的不是重新跑一轮 GA，而是检查：

> 已经找到的好方案附近，是否还存在成本更低、同样严格合格的离散邻居。

如果没有严格合格候选，这一步不会发生。

### 必须用实验回答的问题

1. B 层关键两两覆盖是否覆盖了真正关键的耦合关系；
2. 低压匝数应归铁芯块、低压块，还是独立块；
3. 冷却型号作为独立交叉块后，能否以可接受的精算次数提高严格解质量；
4. 定向变异映射和局部探测次数是否真的提高效率；特别要比较阻抗违规下最近同向高低压油道探测与普通随机回退的改善率，以及负载损耗违规下定向线规变化的改善率；
5. 随机注入比例、交叉率、变异率是否适合不同大小的搜索域；
6. 全组合验证应在哪些小范围产品上使用，作为默认均衡覆盖的对照。

在这些数据出来之前，当前实现应称为“可追溯的 GA 原型和待验证搜索策略”，不能称为已证明最优的工程寻优器。

## 10. 消融策略、严格可行率与真实精算预算

> 先明确适用范围：预算 B / B′ 不是普通 GA 的业务输入，也不是页面日常运行的默认停止条件。普通页面运行和 `ga-run` 都可以不填预算，此时仍按最大代数或停滞规则停止。只有 `ga-ablation` 做同一配置、同一搜索域、同一批随机种子的策略对照时，才要求至少提供一种预算。

### 10.1 消融不再依赖修改源代码

当前 `GASettings` 已支持三项可复核策略字段；它们会随完整设置写入每份 SQLite 的运行元数据：

| 字段 | 当前默认 | 消融时的关闭方式 | 实际含义 |
| --- | --- | --- | --- |
| `coupled_electromagnetic_crossover_rate` | `0.75` | 设为 `0` | 所有交叉改为铁芯、低压、高压、冷却四块探索性重组 |
| `injection_mode` | `empirical_preferred` | `raw_only` | 每代注入强制从页面原始搜索域抽取，不再优先从已精算经验候选重组 |
| `guided_mutation_mode` | `random_only` | 设为 `single_primary` | 日常默认关闭主导约束局部探测，所有变异走普通随机合法变异；完整诊断反馈仅作为可选实验策略 |

因此“消融基线”是**当前代码**明确关闭以上三项改进后的策略；它仍使用同一精算器、同一候选合法化、同一缓存和同一轨迹机制，不是回退或维护旧版本代码。

### 10.2 严格可行率的唯一口径

本文及后续消融统计中的“可行 / 严格可行”只指：

```text
calculable = True
complete = True
feasible = True
```

近可行候选即使总超限很小，也只用于描述距离严格可行域的距离，**绝不计入严格可行率**，也不能拿它的成本同严格合格方案直接比较。

### 10.3 总精算预算 B：安全上限与小预算回归工具

`evaluation_budget=B` 表示本次 GA 最多允许真实调用单设备精算器 `B` 次。缓存命中不增加这一计数；但累计真实精算达到 `B` 后，运行会立即停止，不再继续生成缓存命中、精英复制或下一代候选。它是可选安全上限和小预算回归工具，不是普通 GA 的默认参数。

预算在一代中途耗尽时，最后一条已完成的精算仍会更新双档案；但该代被明确标为“未完整生成，不进入后续演化”。轨迹的 `run_terminations` 表保存预算停止原因、终止代、实际精算调用数和该代是否完整。这样多个策略才是在同一工程计算成本下比较，而不是事后把不同计算量的结果放在一起。

### 10.4 演化预算 B′：把第 0 代公共成本单列

不同产品的第 0 代覆盖规模可能相差很大，而 A/B 覆盖本身不随消融策略改变。为避免总预算 B 大部分被第 0 代消耗，`evolution_evaluation_budget=B′` 只限制**第 0 代完成之后**的真实精算调用：

```text
initial_evaluations   第 0 代实际精算数，作为公共成本单列报告
evolution_evaluations 第 0 代后的实际精算数，受 B′ 硬截止
exact_evaluations     两者之和
```

正式消融推荐固定 B′，并同时报告三项计数。它只用于同一配置内的策略对照，不应用 B′ 的数值比较不同产品；不同产品的搜索域、初代规模和实际计算量本来就可能不同。`evaluation_budget=B` 和 B′ 可以单独使用；同时设置时任一上限先达到即停止，轨迹会写入对应的机器可读终止原因。缓存命中始终不计入两类真实精算预算。

### 10.5 CLI 批次入口

`main.py ga-ablation` 会对同一配置、同一搜索域、同一批种子和同一种预算口径，顺序产生四组独立轨迹：

```text
baseline             三项改进都关闭
coupled              只开启结构电磁耦合交叉
empirical_injection  再开启经验有效域注入
guided_mutation      再开启诊断反馈变异（可选实验策略）
```

命令必须至少提供 `--evaluation-budget B` 或 `--evolution-evaluation-budget B′` 之一。每个“策略 × 种子”都生成带唯一运行 ID 的独立 SQLite；批次还生成 `manifest.json` 和 `summary.csv`，其中分列初代与演化精算数。命令只组织可比实验，不会自动宣称哪一项更优。

### 10.6 当前测试状态与下一步

截至 2026-09-24，已完成 10 条真实 Java 记录的 v9 单设备回归（320/320 个可比字段一致），并完成 A1–A7、B1–B6 的功能与轨迹验证。当前 v9 的配置 401、当前搜索域、B′=8000、10 个配对种子四策略实验显示：经验有效域注入具有成本改善（Hodges–Lehmann=196.625，p=0.03389；5–6/10 改善、0 次变差），但演化精算调用中位数增加 2843.5；耦合交叉未检出额外效应（p=0.5637），诊断反馈变异在注入之上未检出额外收益（p=0.1434）。09-23 又完成 445、415 的跨配置复核：445 各策略均未出现严格解，415 各策略均得到相同最低严格成本，因此这两组只证明默认策略未退化，不能证明某个算子普遍优于其它算子。

因此日常默认采用 `coupled_electromagnetic_crossover_rate=0.75`、`injection_mode=empirical_preferred`、`guided_mutation_mode=random_only`：保留耦合率是因为注入效果在该条件下得到验证，而不是据此证明耦合交叉有效；关闭默认诊断反馈是为了避免在该验证范围内没有额外收益的局部探测调用。`guided_mutation` 命名策略及手动 `single_primary` 仍保留，供其它配置的针对性实验使用。

本轮还验证了：不可计算或结果不完整的后续候选不会进入工作种群；阻抗油道探测只试每侧最近同向合法档位、没有邻居即回退普通随机变异；445 轨迹中的 8 条阻抗偏低探测均按单侧最近油道变化并取得改善；初代恢复采样也已验证能够找到两条可计算候选后进入第 1 代。负载损耗线规定向只沿加宽/加厚/加粗或反向缩小的同类别完整目录记录移动；定向变异基体和运行证据字段可在轨迹回放中识别。

结论边界仍需保留：401 的油道域各只有一个组合，阻抗油道优先的**效果**不能在该配置上判断；“有同向油道邻居但局部探测未改善后回退”的分支仍缺真实实例；也不能把当前代码内四策略比较写成“新 GA 相比历史旧版 GA 更好”。09-24 虽已把全库搜索域构造修到 143/143，但 `Ddyyn11`、`Yy`、`Yd` 共 17 个配置的公式链仍未闭合，不能把“可构域”写成“可寻优”。完整证据见[09-23 批次结项](2026-09-23测试/批次结项说明-2026-09-24.md)、[09-24 当前进度](2026-09-24测试/本批次测试进度.md)、[B6-v9 多种子报告](2026-09-22测试/B6-v9多种子效果实验报告.md)和[09-22 测试结论](2026-09-22测试/测试结论-2026-09-22.md)。
